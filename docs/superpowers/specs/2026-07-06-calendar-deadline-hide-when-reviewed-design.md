# 캘린더 마감일 카드: 리뷰완료 시 숨김 설계

## 배경

캘린더 화면에서 방문 1건이 두 번 표시되는 경우가 있었다: 방문일 카드(초록, "리뷰완료")와 마감일 카드(회색, "리뷰 완료")가 같은 날짜에 함께 뜨면서 같은 가게가 색만 다른 중복 항목처럼 보여 사용자가 헷갈림. 방문일과 마감일이 다른 날짜인 경우엔 같은 방문이 서로 다른 두 날짜에 나타나는 것도 혼란스러움.

마감일 카드/점은 원래 "아직 안 끝난 리뷰 마감을 경고"하는 용도다. `lib/visitStats.ts`의 대시보드 "마감 임박" 목록은 이미 `status !== '리뷰완료'`로 필터링해 리뷰완료 건을 제외하고 있음 — 즉 이 정책은 다른 화면엔 이미 적용되어 있고, 캘린더만 예외였다.

## 정책

**캘린더에서 리뷰완료 상태인 방문은 마감일 카드/점을 표시하지 않는다.** 방문일 카드(상태 표시)만 남긴다.

## 변경 범위

`src/pages/CalendarPage.tsx` 한 파일만 수정.

- `deadlinesByDate` 생성 로직(25-44행 근처)에서 `!v.reviewDeadline`뿐 아니라 `v.status === '리뷰완료'`인 것도 건너뛴다.
- 그 결과 `dayDeadlines`/`selectedDeadlines`엔 항상 미완료 마감만 남으므로, 이 파일 안에서 `deadline.reviewed`를 참조하던 3곳(점 색상, 카드, 하단 상세)은 항상 `false`가 되는 죽은 분기가 된다 — 해당 삼항연산자를 제거하고 "미완료" 쪽 렌더링(빨간 점/`red-500`, `마감 {D-day}`, `리뷰 마감`)만 남긴다.
- `lib/statusStyle.ts`의 `deadlineDisplay`/`reviewed` 필드 자체는 건드리지 않는다 — `TablePage.tsx`, `EditPage.tsx`가 여전히 참조하며, 그 화면들은 방문 1건당 1행이라 중복 문제가 없다.

## 스코프 밖

- `deadlineDisplay` 함수 시그니처나 `reviewed` 필드 제거 — 다른 화면에서 사용 중이므로 유지
- TablePage, EditPage, 대시보드의 마감일 표시 방식 변경 — 이미 올바르게 동작 중, 이번 정책과 무관
